# 003 — Concatenated bundles instead of CDN @require

Date: 2015-05-11 (commit f33d53a)
Status: implemented, shipped

## Context

The project began as a userscript whose header `@require`s pulled
jQuery, lunr, Q, PouchDB, and Handlebars from CDNs. Chrome extension
content-script CSP and offline-ness make CDN scripts awkward, and
non-technical users can't install userscripts. The extension also needs
exactly two script files listed in `manifest.json`.

## Decision

- Declare vendor libraries in `bower.json`; `bower install` materializes
  them under `bower_components/`.
- Gruntfile's `concat` produces:
  - `coursera-fts.lib.js` = lodash + lunr + jQuery + PouchDB + Q +
    Handlebars runtime (in that order).
  - `coursera-fts.js` = compiled `templates.js` + vendored `picomodal.js`
    + hand-written `coursera-searcher.js`.
- `manifest.json` loads exactly those two files as content scripts; the
  userscript header is left in the source as a vestige (including the
  stale `@require` URLs).
- `grunt make` = handlebars compile + concat; `grunt publish` = make +
  webstore upload.

## Consequences

- Works fully offline inside the extension; two-file content script
  loading; single scope for all globals (deliberate, ES5-era style).
- Generated files are committed, so any source change must be followed by
  `grunt make` and both bundles committed in lockstep (1607cce had to
  patch source and bundle together).
- Vendor versions are frozen at 2015 levels; the repo carries known
  Dependabot alerts for them. Upgrades were never the point of this
  archive.
- A zip artifact briefly got committed and was removed in 1607cce; zips
  are now gitignored and regenerated by `publish.rb`.
